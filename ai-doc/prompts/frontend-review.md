# Frontend Review 前端审查提示词

> 用于 AI 执行生产级**前端审查**（Vue 3 + Element Plus）
>
> ⚠️ **本文件是 `frontend-ui.md` 的轻量执行 wrapper**。具体的 20 项审查维度（功能完整性、UI一致性、多语言硬编码、表单校验、权限、异常、响应式、代码质量、上线风险等）**全部定义在 `frontend-ui.md` 中，本文件不复制其内容**。

---

## 审查目标

重点发现可能导致以下问题的前端缺陷：

* 多语言上线受阻（硬编码中文/英文）
* 表单校验缺失导致脏数据入库
* UI 不一致影响专业度
* 假数据 / mock 数据阻塞上线
* 权限按钮未控制
* loading / empty / error 状态缺失
* 前后端接口未真正联通

---

## 审查准备（强制，禁止跳过）

审查前必须按以下顺序阅读：

1. `prompts/frontend-ui.md` ← **审查维度全集（20 章）**
2. `rules/ui.md` ← 本项目 UI 设计规范（色板/间距/组件/按钮/表格/表单/状态）
3. `project-doc/04-FEATURES.md` ← 确认功能蓝图与前后端边界
4. `specs/portal-web/api.md` ← 后端真实接口清单
5. 本次 PR / 审查需求说明（由调用方提供）

阅读完成后**不要马上开始审查**，先输出：

```markdown
### 审查计划

1. **审查范围**：[本次涉及的页面/模块，如 /admin/security-data]
2. **审查维度**：[从 frontend-ui.md 20 章中选择适用维度，不必全选]
3. **审查方式**：[静态代码扫描 / DevTools 运行态 / 截图复核]
4. **排除范围**：[明确不审查的页面，避免范围蔓延]
```

确认后再开始审查。

---

## 审查原则

1. **优先级**：P0 阻塞上线 > P1 严重 > P2 中等 > P3 建议
2. **证据每个问题必须包含：文件路径、行号（或代码片段）、触发场景、线上影响、修复建议、是否需要后端配合
3. **不靠猜测**：信息不足时标注 `⚠️ Needs Verification`，不要凭空假设
4. **不重复 `frontend-ui.md`**：只输出**问题清单**，不复述 20 章规范内容
5. **范围边界**：只审查调用方指定的页面/模块，不顺手审查无关页面

---

## 审查方式（按优先级）

### 方式 1：运行态审查（项目可运行时必做）

在以下分辨率下打开每个核心页面截图复核：

* 1920px / 1440px / 1366px / 1024px / 768px

重点：
* 同页面控件高度是否统一
* 表格是否横向溢出
* 多语言切换后是否撑破布局
* loading / empty / error 状态是否正常

### 方式 2：静态代码扫描（项目不可运行或批量扫描）

必须扫描的文件类型：

* `.vue` / `.ts` / `.js` / `.jsx` / `.tsx`
* 路由文件 `router/index.js`
* i18n 语言包 `locales/*.js`
* API 请求层 `api/*.js`

扫描策略（按 `frontend-ui.md` 第二项"1. 必须扫描的代码模式"执行正则扫描）：

* 裸中文/英文文本节点
* `placeholder="..."` `title="..."` `message="..."` 硬编码
* `ElMessage` / `message.success` / `Modal.confirm` 文本
* 表格列 `title` 硬编码

## 问题等级定义

### P0 阻塞上线

* 核心功能不可用
* 数据提交错误 / 删除无确认
* 权限可绕过
* 页面严重错位不可操作
* 登录、支付、订单等核心链路异常

### P1 严重问题

* 功能不完整但有临时替代
* 表单校验缺失 / 异常提示不清晰
* 硬编码文案影响多语言上线
* UI 规范明显不一致
* 部分权限按钮未控制

### P2 中等问题

* 轻微视觉不统一 / 间距不规范
* 文案可优化 / 交互体验可提升
* 非核心页面存在轻微问题

### P3 优化建议

* 代码可维护性 / 可扩展性建议
* 最多输出 5 条

## 审查后自检（强制）

审查完成后必须逐项自检：

- [ ] 每个问题都包含文件路径和行号（或代码片段）
- [ ] 每个问题都说明了触发场景和线上影响
- [ ] 每个问题都给出了修复建议
- [ ] 需要后端配合的问题已明确标注
- [ ] 信息不足处已标注 `⚠️ Needs Verification`，未凭空假设
- [ ] 评分与问题清单一致（无 P0 时评分不应为 10/10）
- [ ] 上线建议与问题等级一致
- [ ] **未复制 `frontend-ui.md` 的规范内容**

## 审查入口示例

```text
请对 /admin/security-data 页面执行前端审查。

1. 先阅读 prompts/frontend-review.md（本文件）
2. 再阅读 prompts/frontend-ui.md（审查维度全集）
3. 再阅读 rules/ui.md（UI 设计规范）
4. 再阅读 specs/portal-web/api.md（后端接口清单）

阅读后先输出审查计划，确认后再开始审查。

禁止审查 /admin/security-data 以外的页面。
```
